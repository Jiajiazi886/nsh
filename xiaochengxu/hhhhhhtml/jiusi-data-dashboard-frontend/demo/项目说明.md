# 九肆联赛数据分析小程序项目说明

## 1. 文档信息

- 项目名称：九肆·联赛数据分析小程序
- 项目类型：原生微信小程序
- 项目目录：`xiaochengxu/hhhhhhtml/jiusi-data-dashboard-frontend/demo`
- 文档版本：1.0
- 编写日期：2026年9月9日

## 2. 项目概述

九肆联赛数据分析小程序是一套面向帮会联赛数据整理、团队编排和比赛复盘的本地离线分析工具。系统允许使用者分别导入团队配置和比赛数据，再根据团、队、玩家之间的关系完成队伍统计、玩家排行以及自定义分析盒子计算。

项目的核心目标是解决以下问题：

1. 将原始比赛 CSV 数据转换为便于阅读的排行榜和统计结果。
2. 允许团队按照“团 → 队 → 玩家”的层级自由配置。
3. 自动识别一个 CSV 文件中的多个帮会，并选择与当前团队匹配人数最多的帮会。
4. 允许使用者创建多个分析盒子，自由组合队伍、玩家和统计指标。
5. 所有数据保存在微信本地，不依赖服务器、数据库或网络接口。

## 3. 技术方案

项目采用微信小程序原生技术开发：

| 技术 | 用途 |
| --- | --- |
| JavaScript | 页面逻辑、导入解析、状态管理和数据计算 |
| WXML | 页面结构 |
| WXSS | 页面样式 |
| 微信小程序 API | 文件选择、文件读取、本地存储、页面跳转和剪贴板操作 |
| CommonJS | 使用 `require` 和 `module.exports` 组织模块 |
| Node.js Test Runner | 对导入解析和盒子玩家选择纯函数进行测试 |

该目录没有后端服务，也不依赖 npm 安装。主要运行环境为微信开发者工具和微信客户端。

## 4. 系统总体结构

```text
团队配置 JSON ──> 导入校验 ──> 团队、队伍、玩家名单 ──┐
                                                       ├─> 本地状态仓库 ─> 页面展示
比赛数据 CSV ──> CSV 解析 ──> 帮会匹配、玩家指标 ────┘
                                                              │
                                                              ├─> 总览统计
                                                              ├─> 玩家排行
                                                              ├─> 队伍统计
                                                              └─> 自定义分析盒子
```

应用启动时由 `app.js` 加载本地状态。所有页面通过 `utils/store.js` 获取和修改同一份数据，因此导入团队、导入 CSV 或编辑盒子后，其他页面会在再次显示时获得最新结果。

## 6. 页面功能

### 6.1 总览页

总览页用于快速了解当前帮会和各个团的整体情况，主要包括：

- 当前数据集名称、数据人数和队伍数量。
- 各个团的有效参赛人数。
- 击败/清泉、助攻、对玩家伤害和治疗值等核心指标。
- 不同团之间的横向指标对比。
- 可切换统计指标的玩家排行榜。
- 玩家详情和分析盒子的快捷入口。

### 6.2 玩家页

玩家页展示当前 CSV 中所有玩家的排行数据，支持：

- 按玩家名称或职业搜索。
- 自由切换统计指标。
- 按所选指标从高到低排序。
- 点击玩家进入详情页面。
- CSV 中没有加入任何小队的玩家仍会显示在该页面。

### 6.3 玩家详情页

玩家详情页展示单个玩家的完整比赛信息，包括：

- 玩家名称和职业。
- 玩家所属的团与队。
- 全部数据指标及格式化后的数值。
- 玩家相对于全体玩家的指标水平条形图。
- 长按玩家名称复制名称。

### 6.4 队伍页

队伍页按照“团 → 队伍 → 玩家”展示团队结构，主要功能包括：

- 显示每个队伍的配置人数和实际有比赛数据的人数。
- 汇总队伍的击败/清泉、玩家伤害和治疗值。
- 显示队伍成员的职业或“无数据”状态。
- 点击有数据的玩家进入玩家详情页。

### 6.5 盒子页

盒子页是项目的主要操作中心，分为数据装配和分析盒子两部分。

数据装配功能包括：

- 导入团队配置 JSON。
- 导入比赛数据 CSV。
- 查看和复制完整团队配置示例。
- 查看数据人数、团队人数和匹配人数。
- 查看最近一次导入报告。
- 恢复内置默认数据。

分析盒子功能包括：

- 创建多个互相独立的分析盒子。
- 点击盒子名称进行重命名。
- 在指定区域展开或收起盒子。
- 删除盒子。
- 编辑盒子包含的队伍和玩家。
- 编辑盒子显示的统计指标。
- 查看盒子的汇总指标卡片。
- 在“按队伍”和“按玩家”两种表格之间切换。
- 点击表头按照名称、职业、人数或指标排序。
- 单独展开或收起数据表格。

新建盒子默认选择团队配置中的前两支队伍，并默认启用除“资源”之外的指标。

### 6.6 盒子编辑页

盒子编辑页根据入口分为三种模式：

| 模式 | 功能 |
| --- | --- |
| 队伍与玩家模式 | 选择队伍，并继续逐人增加或移除玩家 |
| 指标模式 | 勾选盒子需要显示和计算的指标 |
| 完整模式 | 同时编辑盒子名称、队伍、玩家和指标 |

队伍和玩家编辑具有以下行为：

1. 勾选一支小队时，系统自动选中该小队中具有当前比赛数据的玩家。
2. 取消小队时，系统重新计算基础玩家名单。
3. 使用者可以在小队基础名单之上继续逐人增减。
4. 玩家按照职业分组，职业节点可以独立展开和收起。
5. 可以按照玩家名称或职业搜索。
6. 支持全选或清空当前搜索结果。
7. “按小队重置”会清除手动调整，恢复为所选小队的基础玩家名单。

## 7. 核心数据模型

小程序的运行状态主要由以下对象组成：

### 7.1 玩家 Player

```json
{
  "id": "player_1",
  "name": "玩家名称",
  "role": "职业名称",
  "aliases": ["玩家别名"]
}
```

`aliases` 用于解决简繁体、曾用名或 CSV 名称不一致等匹配问题。

### 7.2 队伍 Team

```json
{
  "id": "team_1_1",
  "group": "进攻一团",
  "name": "一队",
  "playerIds": ["player_1", "player_2"]
}
```

每名团队玩家只能属于一支队伍，队伍通过 `group` 字段归属于一个团。

### 7.3 指标 Metric

```json
{
  "id": "player_damage",
  "label": "对玩家伤害",
  "kind": "number",
  "aggregate": "sum"
}
```

指标分为两种类型：

- `number`：普通数值，例如助攻、伤害、治疗。
- `pair`：成对数值，例如“击败/清泉”和“复活/清泉”。

### 7.4 数据集 Dataset

```json
{
  "name": "༺九肆✈",
  "source": "比赛数据.csv",
  "importedAt": "导入时间",
  "playerIds": ["player_1"],
  "stats": {
    "player_1": {
      "assists": 100,
      "player_damage": 2000000
    }
  }
}
```

### 7.5 分析盒子 Box

```json
{
  "id": "box_1",
  "name": "分析盒子 1",
  "teamIds": ["team_1_1"],
  "manualAddIds": [],
  "manualRemoveIds": [],
  "metricIds": ["kills_spring", "player_damage"],
  "view": "teams",
  "collapsed": false,
  "tableCollapsed": false
}
```

盒子的实际统计玩家由以下公式确定：

```text
有效玩家 = 所选队伍中具有 CSV 数据的玩家
         + 手动添加的 CSV 玩家
         - 手动移除的玩家
```

手动调整不直接复制完整名单，而是保存相对于所选队伍基础名单的差异，从而避免队伍选择和玩家自由选择互相覆盖。

## 8. 团队配置 JSON

团队配置采用固定的“团 → 队 → 玩家”层级：

```json
{
  "version": 1,
  "groups": [
    {
      "name": "进攻一团",
      "teams": [
        {
          "name": "一队",
          "players": [
            {
              "name": "封不覺",
              "aliases": ["封不觉"]
            }
          ]
        }
      ]
    }
  ]
}
```

团队 JSON 校验规则：

- 顶层必须是 JSON 对象。
- `version` 当前支持版本 1。
- `groups`、`teams` 和 `players` 必须是非空数组。
- 团名、队名和玩家名不能为空。
- 同一个团内不能存在重复队名。
- 玩家名称和别名不能指向多个玩家。
- 同一玩家不能同时属于多支队伍。
- 玩家既可以写成对象，也可以直接写成名称字符串。

团队配置文件最大支持 1 MB。导入团队配置成功后，旧盒子会被删除，并创建一个包含所有队伍的“全部队员”盒子。

## 9. 比赛数据 CSV

一个 CSV 可以包含多个帮会区块。每个帮会区块由帮会信息、固定表头和玩家数据组成：

```csv
帮会名称,声明人数
玩家名字,职业,击败/清泉,助攻,资源,对玩家伤害,人伤卸甲,对建筑伤害,破塔卸甲,治疗值,承受伤害,重伤,复活/清泉,焚骨
玩家甲,铁衣,10/2,20,0,100000,0,20000,0,0,150000,3,1/0,0
```

固定字段及内部指标 ID：

| CSV 字段 | 指标 ID | 类型 |
| --- | --- | --- |
| 玩家名字 | — | 文本 |
| 职业 | — | 文本 |
| 击败/清泉 | `kills_spring` | 成对数值 |
| 助攻 | `assists` | 数值 |
| 资源 | `resource` | 数值 |
| 对玩家伤害 | `player_damage` | 数值 |
| 人伤卸甲 | `player_armor_break` | 数值 |
| 对建筑伤害 | `structure_damage` | 数值 |
| 破塔卸甲 | `tower_armor_break` | 数值 |
| 治疗值 | `healing` | 数值 |
| 承受伤害 | `damage_taken` | 数值 |
| 重伤 | `deaths` | 数值 |
| 复活/清泉 | `revive_spring` | 成对数值 |
| 焚骨 | `burn_bone` | 数值 |

CSV 文件最大支持 5 MB。解析器支持双引号字段、双引号转义以及 Windows 和 Unix 换行符。

以下问题会阻止导入：

- 缺少帮会名称和声明人数。
- 缺少固定字段头或字段顺序错误。
- 字段数量错误。
- 玩家名称为空。
- 同一帮会中出现重复玩家。
- 普通指标不是有效数字。
- 成对指标不是“数字/数字”格式。
- CSV 中存在未闭合的双引号。

帮会声明人数与实际读取行数不一致不会阻止导入，但会在导入报告中显示警告。

## 10. 玩家名称匹配

系统在匹配团队玩家和 CSV 玩家时会执行名称标准化：

1. 删除 UTF-8 BOM。
2. 删除首尾空白。
3. 转换为小写形式。
4. 忽略名称中的空格。
5. 统一忽略名称尾部的 `丶`、`丷`、`·`、`•`、`・` 等点号。
6. 同时使用玩家的正式名称和 `aliases` 别名进行匹配。

如果不同玩家的名称或别名标准化后相同，团队 JSON 会被拒绝，避免一条 CSV 数据同时匹配到多个玩家。

## 11. 多帮会自动选择

CSV 中存在多个帮会时，系统会为每个帮会计算与当前团队的匹配情况，并按照以下优先级选择：

1. 匹配玩家数量最高。
2. 匹配率最高。
3. 在 CSV 文件中出现位置靠前。

导入报告会显示检测到的帮会、最终选择的帮会、团队匹配人数、CSV 未编队人数、团队缺少数据人数和全部候选帮会的匹配结果。

如果所有帮会的匹配人数均为零，系统仍会选择文件中的第一个帮会，但会明确显示零匹配警告。

## 12. 两种导入操作的影响

### 导入团队 JSON

- 替换当前团、队和团队玩家关系。
- 尝试与已有比赛数据玩家进行名称或别名匹配。
- 保留当前比赛数据。
- 清空旧分析盒子。
- 创建“全部队员”盒子。
- 生成团队导入报告。

### 导入比赛 CSV

- 保留当前团队配置。
- 保留当前分析盒子。
- 替换当前比赛数据集和指标数据。
- 自动选择匹配度最高的帮会。
- 清理已经失效的手动玩家引用。
- 保留仍然有效的盒子队伍、玩家和指标设置。
- 生成比赛数据导入报告。

所有解析和校验完成后才会提交新状态。导入过程中发生错误时，原有状态不会被替换。

## 13. 本地存储

项目使用 `wx.setStorageSync` 和 `wx.getStorageSync` 保存状态：

- 当前存储键：`jiusi_mp_state_v3`
- 旧版兼容键：`jiusi_mp_state_v2`

应用优先读取 v3 状态。如果 v3 不存在或无效，会尝试读取 v2，并将有效的 v2 状态迁移为 v3。旧键不会被主动删除，便于回退。

因为数据只保存在当前微信环境中，所以目前不支持账号同步、跨设备共享或云端备份。卸载小程序、清理微信数据或清除开发者工具缓存可能导致本地状态丢失。

## 16. 使用方法

### 16.1 在微信开发者工具中打开

1. 启动微信开发者工具。
2. 选择“导入项目”。
3. 项目目录选择本说明文档所在的 `demo` 目录。
4. 确认项目类型为“小程序”。
5. 导入后等待开发者工具完成编译。

### 16.2 导入团队配置

1. 打开底部“盒子”页面。
2. 点击“导入团队配置”。
3. 从微信会话文件中选择 `.json` 文件。
4. 查看识别到的团、队伍和玩家数量。
5. 确认后完成导入。

### 16.3 导入比赛数据

1. 打开底部“盒子”页面。
2. 点击“导入比赛数据”。
3. 选择符合固定字段格式的 `.csv` 文件。
4. 系统自动解析多个帮会并选择匹配度最高的帮会。
5. 在页面顶部查看导入报告和匹配人数。

### 16.4 创建分析盒子

1. 点击“新建分析盒子”。
2. 点击盒子名称可修改名称。
3. 点击队伍区域的“编辑”选择队伍并自由调整玩家。
4. 点击“改指标”选择需要分析的数据。
5. 返回盒子页面查看汇总卡片和详细数据表格。

## 17. 项目特点

- 团队配置和比赛数据完全解耦，可以分别替换。
- 支持一个 CSV 中存在多个帮会。
- 支持玩家别名和名称标准化匹配。
- 支持未编队 CSV 玩家参与自定义盒子。
- 支持小队自动选人和玩家自由增减同时存在。
- 盒子配置可持久化保存。
- 导入过程采用先校验后提交方式，避免错误文件破坏原数据。
- 使用稳定的内部指标 ID，避免中文 CSV 列名直接参与业务计算。
- 整体采用深色紫色视觉体系，适合密集数据阅读。

## 18. 当前限制

- 数据仅保存在本机，暂不支持云同步和多人共享。
- 团队配置和比赛数据需要使用规定格式。
- 当前没有历史比赛管理功能，一次只维护一个活动数据集。
- 当前没有登录、权限控制和后台管理功能。
- 大量玩家和指标同时显示时，详细表格需要横向滚动。
- 团队中没有对应 CSV 数据的玩家不会参与统计。
- 文件选择依赖微信提供的消息文件选择能力。

## 19. 可扩展方向

后续可以在现有结构上扩展：

1. 增加多场比赛历史记录和赛季管理。
2. 增加数据趋势图和多场比赛对比。
3. 增加团队配置可视化编辑器和 JSON 导出。
4. 增加盒子配置复制、导入和导出。
5. 增加云端存储、登录和跨设备同步。
6. 增加不同职业的专属评价指标。
7. 增加比赛报告图片或 PDF 导出。
8. 增加异常数据提示和数据质量评分。

## 20. 总结

九肆联赛数据分析小程序将团队组织关系、原始比赛数据和自定义分析场景统一到一个离线微信小程序中。团队 JSON 决定“人员如何组织”，比赛 CSV 决定“玩家产生了什么数据”，分析盒子决定“本次需要组合哪些人并观察哪些指标”。这种解耦设计使同一套程序能够适应不同团队、不同帮会和不同比赛数据，同时保持使用流程简单、数据计算可追踪且导入失败可恢复。
