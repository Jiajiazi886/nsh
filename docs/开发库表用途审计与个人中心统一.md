## 个人中心

原 `/user/profile` 是若依登录账号资料页，含手机号、邮箱、角色和密码；`/personal/profile-edit` 是账号所属的游戏玩家资料页，因此此前展示不同。

现统一：

- 唯一规范入口：`http://127.0.0.1:5173/personal/profile-edit`。
- 旧 `/user/profile` 仅兼容重定向，不再显示旧页面；头像与个人管理菜单均访问同一表单。
- 删除旧页面及其账号信息／头像子组件；登录密码组件移为独立弹窗，旧 `/user/profile/resetPwd` 会转到同页的密码弹窗。
- 游戏名字、UID、微信号、橙武、主副职业和备注继续与两个小程序共用同一账号资料接口；不混入登录密码，不改登录账号名。

## 已实际优化

`guild_member` 原来只有主键、帮会 ID、玩家名索引，没有个人资料使用的账号关联索引。

已增加两个非唯一索引，不删除或合并任何成员：

| 索引 | 字段 | 对应查询 |
| --- | --- | --- |
| `ix_guild_member_account_active_id` | `member_user_id, is_active, member_id` | 本人最新有效绑定、资料同步 |
| `ix_guild_member_owner_active_account` | `user_id, is_active, member_user_id` | 本帮会成员范围与管理查看权限 |

最新成员预填及管理存在性查询增加 `LIMIT 1`。以同一审计 SQL 的 EXPLAIN 对比，查询由无账号候选索引、主键过滤扫描，变成 `ref` 使用 `ix_guild_member_account_active_id`，并显示 `Using index`；没有据此承诺具体耗时或生产吞吐量。

迁移 `ruoyi-fastapi-backend/tools/optimize_player_center_dev.py` 校验目标库全名；复用已覆盖相同前缀的索引，名称冲突则停止，不覆盖旧索引。已经执行两次：第一次创建两个索引，第二次不重复创建。ORM 定义也保持一致。

## 为什么不能把账号、资料和成员合成一张表

| 表 | 职责 |
| --- | --- |
| `sys_user` | 登录账号、密码、账号状态；与角色权限关联 |
| `integration_account_player_profile` | 一个账号的一份游戏玩家资料及私人微信号 |
| `guild_member` | 帮会内成员、组织身份与绑定关系；一个账号可能存在多条成员记录 |

删旧 UI 不等于删账号表。合并成员与资料会破坏组织权限或把私人微信号带入成员／公开接口。已有历史快照仍保留当时阵容，不能追改。

## 审计结论

2026-09-16 清理后实查 **56 张表**；行数会随联调继续变化。未发现声明的外键或触发器，但应用层仍有大量关联，这不代表可以随意删表。

按结构分组：16 张账号／系统表，14 张帮会／旧约战排表表，8 张共享活动／玩家资料表，14 张内功／面板／计算器表，另有 AI 模型、迁移记录及 2 张代码生成表。

当前元数据估算数据和索引约 31.5 MiB；两个图片／面板识别历史表仍占绝大多数空间。如果目标是继续节省空间，应先讨论历史图片保留期限或改为文件引用，而不是按空表批量删除；本次没有清空这些历史数据。

### 已完成的定点清理

- `guild_info`：0 行；未发现 ORM、SQL 运行时、视图、存储过程、事件、外键或触发器依赖。
- `guild_review`：0 行；审核管理已下线，未发现表级代码或数据库对象依赖。

两项经过固定允许名单迁移 `tools/cleanup_obsolete_activity_dev_tables.py` 删除。迁移拒绝其他数据库，任一表非空都会在首个 `DROP` 前停止，重复执行不会继续删除。恢复结构保存在 `sql/20260916_obsolete_guild_tables_recovery.sql`；清理时两表均无业务行。

### 只能按模块退役、不能按空表批量删

- `gen_table`、`gen_table_column`：代码生成模块仍有 DAO／接口；不用代码生成时应先退出该模块和菜单。
- `apscheduler_jobs`、`sys_job`、`sys_job_log`：调度模块和 APScheduler 存储使用；开发启动不执行旧定时任务，表不等于垃圾。
- `guild_schedule*`：旧排表、团队、小队、人员关系及表格工作簿仍有数据和接口。应另做旧模块退役、历史读取／迁移方案，不能直接删旧表。
- `integration_activity_report`：虽然当前为空，但真实共享战报关联接口需要它。
- `sys_dept`、日志和其他空配置表：权限、运维或相应业务模块仍引用。
