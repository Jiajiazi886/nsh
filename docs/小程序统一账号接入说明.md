# 小程序统一账号接入说明

更新日期：2026-09-14。

## 账号方案

网页与小程序复用共享后端现有的 SysUser 账号、密码校验、角色、权限、验证码和 JWT 会话。没有新增“小程序用户表”，不按昵称创建或绑定账号。直接使用原网页版的账号密码登录。

小程序使用 JSON 登录 `/api/v1/auth/login`；后端调用现有带限流和审计的登录入口，不另发一种身份凭证。登录成功后请求当前账号信息，确认后才进入工作台。

微信绑定、一键登录和微信机器人仍未启用。统一账号不代表自动绑定微信身份。

## 修改位置

仅修改独立副本 `E:/nsh/nshls/RuoYi-Vue3-FastAPI-miniapp-backend`，当前分支 `xiaochengxu`。原毕业项目保持只读。

两个小程序入口均已更新：

- `xiaochengxu/hhhhhhtml/jiusi-data-dashboard-frontend/demo`：保留联赛分析和盒子的原 demo 工程。

两者使用相同的账号服务与登录过期处理。主工程保留 `/getInfo` 和 `/register` 的旧响应契约，兼容已有个人资料和注册页面；这些接口也属于同一个共享后端、同一套账号，不是第二套用户系统。

## 接口

| 用途 | 方法与路径 | 说明 |
| --- | --- | --- |
| 登录配置 | GET `/api/v1/auth/config` | 注册、验证码开关 |
| 验证码 | GET `/api/v1/auth/captcha` | 复用现有验证码机制 |
| 账号登录 | POST `/api/v1/auth/login` | `userName/password/code/uuid` |
| 当前账号 | GET `/api/v1/auth/me` | 服务器校验会话与账号有效性 |
| 退出 | POST `/api/v1/auth/logout` | 撤销当前会话 |

登录请求不携带旧账号 token。密码仅用于请求，不写入本地缓存。业务请求携带 `Authorization: Bearer <token>`。

存储中的 token 不能直接视为有效登录。重新打开登录页时会先向后端确认；认证失败退出到登录页，断网时保留会话并显示错误和重试入口。旧请求返回 401 不会清除后来新登录的账号。

退出或认证失效时同时清理本地和内存账号信息。退出请求失败时仍允许退出本机，但明确提示“后端退出未确认”，不声称服务端会话已撤销。更换后端根地址会丢弃已标记为旧地址的会话。

## 后端地址与联调

两个入口的 `config/env.js` 中设置后端根地址，不要添加 `/api/v1`，请求层会自动添加。

当前本地配置：`http://127.0.0.1:9100`。必须运行含上述统一接口的独立副本后端，并确保网页也指向同一后端、使用同一账号数据库，否则仅修改小程序地址无法让两套数据库的账号自动统一。

当前体验版／正式版配置沿用已有正式域名的 `/prod-api` 根地址。本次没有验证或更新该域名正在运行的服务。正式使用前必须确认其已部署对应版本。

手机上的 `127.0.0.1` 指向手机，不是开发电脑；真机联调需配置能访问的后端地址，发布环境需完成微信请求域名配置。不要在正式包中使用本地回环地址。

共享后端现有开发配置 `APP_SAME_TIME_LOGIN=true`，支持网页、小程序分别保有会话；关闭该配置将执行原后端单会话策略，可能导致另一个端被退出。小程序不会绕过后端策略。

账号接口不依赖 `NSH_ACTIVITIES_ENABLED`。约战活动接口仍需要按《约战信息实现与验收说明》部署其独立表并启用功能；该功能未启用不等于账号不能登录。原 demo 的离线 CSV 分析仍是离线分析，不冒充服务器战报。

本次没有迁移、连接真实数据库，没有启动或重启运行中的服务，没有使用真实账号密码，没有操作微信开发者工具或真机。
