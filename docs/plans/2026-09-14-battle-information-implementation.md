# 约战信息实施记录

实施范围：独立副本，原项目只读，不连接真实 MySQL/Redis，不重启服务，不自动部署或迁移。

已确认：网页两个菜单复用我的约战、找约战、历史战报与隐藏详情；PC 左帮会右俱乐部，小程序分类切换；组织阵容成员只读，公开活动可按资格报名/请假；十秒本地草稿，显式保存原子生成多版本快照。

## 工作切片

1. 测试先行：组织授权、快照事务/版本/幂等、六席/职业/替补、公开报名、历史范围。
2. 新增活动、组织/俱乐部授权、快照、报名与战报关联表；仅提供手动迁移。
3. 实现统一 v1 列表、详情、组织候选、保存/发布/结束、报名/请假、战报显式关联。
4. 对齐当前原项目排表源码到副本；以活动为独立草稿边界，保存走新事务接口，保留旧排表只读历史。
5. 网页两处菜单共用页面；小程序主项目与嵌套 demo 活动页均对接相同接口；无假数据回退。
6. SDK、纯函数和隔离 HTTP/SQLite 测试，Vue 编译、小程序语法/WXML 检查，交付运行与迁移说明。

上述切片已完成源码与隔离验证。交付说明见 `docs/约战信息实现与验收说明.md`。真实库迁移、服务加载、微信开发者工具和真机验收未执行；不得据此宣称已上线。

## 实施约束

- 帮会旧数据以所属管理账号作为组织来源；本人通过 member_user_id 校验，不能使用昵称或 GuildMember.user_id 充当本人。
- 俱乐部缺少旧实体，因此提供最小俱乐部创建及基于真实账号绑定成员的授权接口；仅组织所有者可授予助手权限。
- 阵容快照不可修改；报名状态覆盖只读当前席位视图，结束时冻结最终阵容。对外仅展示安全 DTO。
- 未关联旧战报保持原样，不按标题/时间自动关联。新关联必须由拥有该战报和目标活动管理权限的账号明确操作。
- 不接入机器人、微信一键登录，不声称真实 MySQL 并发或真机已验收。
