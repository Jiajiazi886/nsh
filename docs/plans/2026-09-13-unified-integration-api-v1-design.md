# 多端统一后端接口与接入包设计

状态：用户已确认方案，开始在独立副本实施。本文是实施设计，不代表接口、迁移、SDK 或微信联调已完成。

## 1. 本次要达到的结果

网页、微信小程序及后续微信机器人共用现有若依账号、业务服务和权限来源。交付不止接口命名说明，还应包含经过测试的后端实现、机器可读契约、客户端封装、接入示例和可分发接入包。

实施目录：`E:/nsh/nshls/RuoYi-Vue3-FastAPI-miniapp-backend`。原项目后端和真实 `ruoyi` 库不直接修改、迁移或作为自动化测试目标。现有运行服务暂不重启；确认部署时再切换验证后的版本。

当前已规划的模板、活动、六席位阵容、快照、CSV 分析、机器人通知仍沿用既有业务设计。统一接口层不能把未实现业务包装成成功响应；能力清单必须区分可用、禁用和未实现。完成接口基座也不能被描述成整个活动闭环已经完成。

## 3. 方案选择

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| A：同一 FastAPI 业务服务，加版本化接口与兼容适配 | 三端同账号、同权限、同数据；旧网页可渐进迁移 | 需要接口盘点和明确身份边界 | 推荐 |
| B：直接修改全部旧路径、字段和返回格式 | 看起来最统一 | 旧网页登录、分页、下载容易全部受影响 | 不采用 |
| C：另做小程序/机器人后端并同步账号和业务 | 各端开发独立 | 密码、权限、活动状态分裂，同步难以保证 | 不采用 |

统一业务命名空间暂拟为 `/api/v1`，取代此前尚未实施的分散业务命名草案。机器人内部入口单独放在 `/internal/bot/v1`，但仍属于同一后端、调用同一服务。现有已实现的 `/login`、`/guild/*`、`/personal/*`、`/system/*` 等保留兼容。

### 系统结构

```text
网页 ──────────┐
小程序 ────────┼── /api/v1 ── JWT / 账号状态 / 业务权限 ──┐
其他授权客户端 ┘                                         │
                                                        ├── 同一业务 Service ── 带归属条件的 DAO
微信 iLink ── 经验证的通道适配器 ── 服务身份 / 重放防护 ──┘           │
                         │                                    事务 / 审计 / Outbox
                    微信身份 → 绑定账号                                │
                                                           受控通知 worker → 通道
```

后台管理 API 不因增加小程序入口而向普通用户或机器人开放。JWT 证明“是谁”，权限和对象归属决定“能做什么”。

## 4. 认证与请假规则

### 4.1 统一账号认证

- 第一版账号密码登录，复用现有密码校验、验证码、登录限流和 Redis 会话；客户端不持久化密码。
- 请求统一使用 `Authorization: Bearer <token>`，服务端固定允许的签名算法，验证 exp、合法 user_id 和 session_id、对应 Redis 会话、账号存在及未停用。
- 缺令牌、坏格式、过期、签名错误、会话撤销或账号停用都返回 401，不能变成 500，也不能继续执行 DAO 写操作。
- 权限从数据库及当前会话业务上下文获取，不信任客户端提交的 roles、userId、guildId 或职业来提升权限。
- 同账号多端会话复用现有多会话机制；退出当前端只撤销当前会话。强制下线和停用账号的边界需要测试覆盖。
- 小程序微信绑定及一键登录预留独立契约。未配置真实服务端微信身份验证时明确返回不可用，不用任意 code、昵称或 openid 模拟登录成功。

### 4.2 每次本人请假/报名

新接口不需要客户端选择任意申请账号。若提交 memberId，则它只能用于定位登录账号已经绑定的、本邀请所属帮会的有效成员。

```text
有效 JWT
  → 当前账号
  → 有效邀请及所属帮会
  → member_user_id == 当前账号，成员有效且在该帮会
  → 校验报名/请假状态
  → 事务保存，applicant_user_id = 当前账号
```

- 未绑定成员时返回明确业务错误，提示先完成账号与成员绑定；不按同名、手机号或职业自动认领。
- 不能请假他人，不能通过更换 memberId、inviteCode 或 guildId 跨帮会写入。
- 请假与报名互相替换必须属于同一个本人、同一个邀请，并在同一事务内完成。
- 重试使用账号和操作范围隔离的幂等键。同键同内容返回原结果；同键不同内容返回 409。并发不能同时保留互相冲突的有效记录。
- 管理员/助理代办若启用，必须是另一条管理命令：检查本帮权限，记录实际操作者、被代办者及原因；不能借本人接口冒充。
- 旧公开请假、报名路径也加账号验证和归属检查，保留原成功返回格式。匿名提交不再兼容，这是有意的安全修正；旧网页表单须按迁移说明先登录。
- 本次不自动把历史 applicant_user_id=0 的记录认领给任何账号，历史保留并标记来源。

### 4.3 有限公开入口

匿名入口使用明确 allowlist，例如认证配置、验证码、登录、允许公开的活动摘要。公开 DTO 不返回联系方式、完整私有名单、房间密码或后台权限。

本人请假、报名、退出、改资料、绑定、上传及其他业务写操作不得放入匿名 allowlist。机器人服务入口使用独立服务认证，不作为“免 JWT 的普通客户端接口”。

## 5. 接口契约

### 5.1 返回与字段

新接口统一 camelCase；身份及数据库 BigInteger ID 以字符串传输，避免 JavaScript 精度丢失。分页统一 data.items / page / pageSize / total。大整数指标有单独的精确数值序列化规则，不随手转浮点数。

```json
{
  "code": 200,
  "msg": "操作成功",
  "success": true,
  "requestId": "req_example",
  "data": {}
}
```

失败包含稳定 errorKey；新接口的 HTTP 状态与业务状态对应：401 未认证、403 无权限、404 不存在或不可见、409 冲突、413 文件超限、422 参数问题、429 限流、503 能力未启用/上游不可用。异常详情、SQL、密钥、绝对文件路径不返回给客户端。

旧 API 的返回、分页和文件下载保持兼容，不通过全局修改 ResponseUtil 破坏现有网页。上传/下载保持二进制处理和真实权限检查。

### 5.2 接口模块

| 模块 | 拟接口 | 身份与范围 |
| --- | --- | --- |
| 契约能力 | GET /api/v1/capabilities | 最小公开能力信息，不泄漏管理配置 |
| 账号 | /api/v1/auth/config、captcha、login、me、logout | 登录/配置为有限公开；其他 JWT |
| 微信预留 | /api/v1/auth/wechat/* | 真实 code 验证；未配置则不可用 |
| 本人归属/申请 | /api/v1/me/organizations、membership、join-applications | 本人 JWT，共用现有入会规则 |
| 职业/成员 | /api/v1/organizations/{id}/professions、members | JWT + 本组织能力；职业树与颜色统一 DTO |
| 约战邀请 | /api/v1/invitations、/invitations/{code} | 管理端与公开摘要分离 |
| 本人请假/报名 | /api/v1/invitations/{code}/leave、signup、my-status | JWT + 本人绑定 + 有效邀请 |
| 申请审核 | /api/v1/organizations/{id}/registrations/* | 管理员/授权助理、本组织范围 |
| 团队/当前排表/历史 | /api/v1/organizations/{id}/teams、schedules/* | 复用现有服务，成员不能直接写管理阵容 |
| 模板/活动阵容/快照/抢位 | /api/v1/templates、activities、lineups、snapshots、signups | 沿用既有业务设计；各项实现与能力清单一致，不用空成功占位 |
| CSV/比赛/分析/盒子 | /api/v1/imports、battles、analysis-runs、boxes | 真实组织、活动/快照/run 归属；文件不能绕过校验 |
| 个人资料及现有工具 | /api/v1/me/profile、personal/* | 本人资料及现有工具权限，不复制用户体系 |
| 后台系统/监控 | 原 /system/*、/monitor/* 的独立契约分类 | 保留后台权限；不塞进机器人查询工具 |
| 通知偏好 | /api/v1/me/notification-preferences | JWT + 本人 opt-in，默认不订阅 |
| 微信身份绑定 | /api/v1/me/bot-binding/challenges、bindings | JWT + 本人；短时一次性挑战/解绑 |
| 机器人服务 | /internal/bot/v1/events、queries、deliveries | 服务认证、绑定身份、工具 allowlist，不接受任意用户 ID |

每个已注册操作必须进入接口目录，注明：业务模块、当前旧路径、v1 路径/兼容方式、公开/账号/组织/管理/服务认证类别、请求模型、返回模型、对象权限、迁移状态及验证用例。不能仅通过给路径加前缀就声称权限已经审计完成。

部署 API 根路径与版本命名空间分别配置，避免重复拼接 /dev-api、/prod-api 或 /api/v1。SDK 不硬编码真实服务器地址。

## 6. 微信机器人/iLink 接入

### 6.1 服务身份与用户身份分开

微信消息里的姓名、文字 userId、手机号或 openid 都不能直接变成系统登录身份。

1. 系统账号使用 JWT 获取短期一次性绑定挑战，默认有效 5 分钟，只存摘要并限流。
2. 用户把挑战交给机器人；可信通道从真正入站消息提取 channel / app / botAccount / subject。
3. 后端验证服务来源后原子消费挑战，绑定该微信身份与系统账号；重复、过期、冲突绑定拒绝。
4. 查询时按当前绑定重新获取账号及组织能力。停用账号或解绑后立即失去私人查询及通知资格。

绑定是耐久业务数据，不只存在进程内字典。机器人不会保存系统密码、索取管理员 token，或者将微信机器人身份与小程序微信身份默认合并。

### 6.2 内部服务接口

- 优先采用带 keyId 的 HMAC 服务签名，覆盖方法、规范化路径、时间戳、nonce 和原始 body 摘要；常量时间比对、时间窗口、重放缓存、大小限制和密钥轮换都要测试。
- 服务认证成功不等于拥有全站用户权限；后端只从已验证入站身份查绑定，业务层继续检查本人/本帮/公开范围。
- messageId 做入站去重，重复事件不能重复绑定、上传确认或触发通知。
- 查询工具只开放明确名单：公开活动数量、指定职业缺口、本人可报、本帮职业人数、允许查看的报名/请假人数。私有房间信息和密码不进入公开响应。
- 第一版不把自由聊天直接转换为写命令。后续个人写工具需要用户确认和限动作、限对象、短期委托凭证，再进入同一业务权限链。
- CSV 用受认证文件引用/上传入口，未确定活动时进入待处理；匹配仅给建议，必须由有权限账号确认，不因文件/聊天里的指令提升权限。

这套内部 events 契约是本系统的可信桥接协议，不能冒充微信官方 webhook。实际 iLink transport 要依据可核验 SDK/协议实现身份和上下文处理；尚未验证的主动发送、群聊、文件或小程序卡片能力不承诺可用，默认关闭。

### 6.3 通知与扩展

采用用户主动订阅、职业筛选、事务 Outbox、发送前再次检查绑定/权限、幂等投递、重试/退避及死信。业务提交成功不能因微信发送失败被回滚，也不能把失败报成已发送。

机器人文档中的补人房间信息、CSV 待处理、查询和偏好统一调用共享服务。后续 MCP 暴露同一工具 allowlist，不开放任意 SQL、全站查询或未经确认的管理写操作。知识库只作为信息来源，不决定授权。

## 7. 实施顺序与验证

1. 建立测试防护与接口清单：测试显式隔离数据库、Redis、上传路径；拒绝真实 ruoyi 目标；不运行正式 app lifespan 的自动补齐或定时任务。
2. 测试先行加固 JWT/会话/账号状态和本人归属；同时修复旧请假、报名入口，验证失败路径写操作为零。
3. 实现版本化认证、标准响应/错误/分页、权限上下文、业务适配、稳定 operationId 和 OpenAPI。盘点全部现有操作，不默默放宽后台权限。
4. 按既有业务设计实现/接入活动、阵容、快照、导入和分析接口；同步标注未完成项，不能以基座替代完整业务需求。
5. 实现绑定、服务签名、入站去重、白名单查询、通知与 transport 接口。假通道验证业务，实际微信验证另有明确证据。
6. 提供 fetch / wx.request 可注入传输的 JavaScript SDK、Python 客户端、Postman 集合及调用示例。
7. 回归旧网页接口，生成契约及接入包，检查包内容、接口与示例一致性；再提交部署/迁移方案供确认。

### 必须提供的验收证据

- 认证：空 token、坏格式、错误签名、缺 exp/session/user、过期、撤销、停用账号、多端登录/分别退出。
- 归属：本人成功、他人 memberId、跨帮会邀请、未绑定成员、管理员身份不能冒充成员本人。
- 状态：请假/报名替换、重复与并发、幂等键内容冲突、失败不取消旧记录、不部分写入。
- 路由：旧公开请假/报名和新接口同样拒绝匿名；所有新业务写路由都有实际身份保护，不只 security 文档标记。
- 契约：正常/错误/分页/字符串 ID/二进制下载正确；OpenAPI 操作标识唯一；旧返回不破坏。
- 机器人：服务签名、过期/重放、假 subject、跨 bot/app 身份、绑定码重复、解绑/停用、工具白名单、私人数据隔离。
- 通知：只向订阅且有权限账号发送，不重复，失败可重试，解绑后不再发送。
- 隔离：测试不能连接真实库/Redis、不能触达真实微信或用户，迁移不会随测试导入自动执行。
- 接入：SDK 在模拟 fetch、wx.request 和 Python 传输中跑通认证、错误及业务调用；包中示例与契约一致。
- 完整业务：活动/阵容/快照/CSV/分析是否可调用逐项证明，缺失项明确列出，不能拿 JWT 单元测试替代整套后端验收。

## 8. 最终交付包

拟输出 `release/unified-backend-integration-v1.zip`，包含已实现的后端模块、明确的增量迁移、无真实凭证的配置样例、业务/后台/机器人分组契约、OpenAPI、错误码、权限矩阵、SDK、Postman、示例、版本兼容说明、测试报告及文件清单/校验和。

不包含真实 .env、数据库备份、登录 token、微信凭证、RSA 私钥、日志、node_modules、虚拟环境或个人路径。示例凭证不可直接用于生产；运行配置必须显式设置必要密钥。打包前做秘密扫描和归档内容核查。

如需下载 SDK、依赖或协议资料，下载目录和缓存放在本副本的 `.artifacts` / `.cache`，不放 D 盘。当前设计核查只读取了在线 SDK 元数据，没有下载或安装新依赖，也没有连接真实微信。

用户已确认按“同账号 JWT + /api/v1 共享业务 + 旧网页兼容 + 安全机器人桥接 + 独立副本接入包”方案实施。代码和迁移文件在独立副本开发；迁移不应用到真实库，不重启当前真实连接服务。部署/真实微信启用仍需另外确认。
