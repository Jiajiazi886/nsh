# 约战排表本地草稿改造

2026-09-13，按用户明确指定的保存方案实施，仅修改原项目约战排表相关前端。

## 用户已指定的设计

- 团队内的小队竖向排列，每小队仍是一行六个位置，进一步缩小卡片与间距。
- 选择玩家窗口的职业树每次打开都默认收起。
- 排人、移动、清空、创建/删除团队与小队、临时替补均只修改内存草稿，不每次写后端或刷新。
- 浏览器 IndexedDB 每 10 秒保存一次完整草稿，按账号、接口环境和当前排表隔离；恢复页面时读取自己的草稿。
- 新增“保存”按钮，点击后将草稿同步现有后端。普通定时保存不能调用后端写接口。
- 保留历史：加载历史只替换本地草稿；“保存历史”属于明确的保存操作，先同步草稿，再保存后端快照。

## 实施清单

1. 纯函数测试先行：本地增删、移动交换、六人限制、临时元数据保留、历史临时位置映射。
2. 实现 IndexedDB 草稿读写与串行写入；页面离开时补存，失败明确提示，不假报保存成功。
3. 实现手动同步器：复用已有团队/小队创建删除、小队批量分配和 workbook 接口，不新增后端或改库。
4. 同步前校验，检测后端并发修改；保存中禁用编辑。多接口同步可能部分成功，保留草稿和进度，重试不能重复创建。
5. 修改盒子组件和父页面，仅手动保存时读写后端；左侧保留布局，其排人状态来自即时草稿。
6. Node 单元、隔离无头 Chrome（全部模拟 API）、SFC 编译和构建验证。覆盖定时只写 IndexedDB、刷新恢复、职业默认收起、多个小队竖排、紧凑六位置、手动保存、失败重试及历史。

不改真实排表做测试，不改后端或数据库，不操作用户桌面，不提交、合并或推送原项目。用户未选择子代理，由当前代理实施。全流程技能附加 references 缺失，按主技能先测试后实现和审查。

- 原项目约战排表已改为完整本地草稿编辑，创建/删除团队与小队、玩家分配交换清除、临时成员均不请求后端。
