## 1. 完整目标与边界

过去的原项目只读要求在本次明确要求的界面范围内调整；其他源代码、原有成员业务、后端及数据库结构不在本次改造范围内。本草案先保存在独立副本中，不能被误认为原项目已经改造完成。

## 3. 界面结构

```text
帮会管理
└─ 分团管理
   ├─ 团队管理：暂未开发
   └─ 约战排表
      ┌─────────────────┬─────────────────────────────────────┐
      │ 原帮会成员区    │ 创建团队 | 保存历史 | 历史查询      │
      │ 搜索/筛选       │ ┌─────────────────────────────────┐ │
      │ 职业树/颜色     │ │ 进攻一团             收起 | 删除│ │
      │ 临时补人        │ │ 一队  0/6            删除小队   │ │
      │ 可拖拽成员      │ │ [1][2][3][4][5][6]             │ │
      │                 │ │ 二队  0/6            删除小队   │ │
      │                 │ │ [1][2][3][4][5][6]             │ │
      │                 │ │ + 在该团队创建小队            │ │
      │                 │ └─────────────────────────────────┘ │
      └─────────────────┴─────────────────────────────────────┘
```

团队不直接接收玩家；只能拖到小队的具体位置。展开/收起按钮只改变展示状态，不改变人员分配或触发其他操作。删除团队/小队必须确认，并明确成员只是移出当前排表，不从帮会成员库删除。

## 4. 已核对的接口与行为

以下接口已存在，非拟新增：

| 操作 | 接口 |
| --- | --- |
| 读取当前排表 | GET /guild/schedule/current |
| 创建/删除团队 | POST /guild/schedule/team；DELETE /guild/schedule/team/{teamId} |
| 创建/删除小队 | POST /guild/schedule/team/{teamId}/squad；DELETE /guild/schedule/team/{teamId}/squad/{squadId} |
| 成员分配/清除 | PUT /guild/schedule/assignment；DELETE /guild/schedule/assignment/{memberId} |
| 保存/读取历史 | POST /guild/schedule/snapshot；GET /guild/schedule/history；GET /guild/schedule/{scheduleId} |
| 应用历史 | POST /guild/schedule/history/{scheduleId}/apply |
| 读取/保存附加元数据 | GET /guild/schedule/current/workbook；PUT /guild/schedule/current/workbook |

当前成员分配请求使用 member_id、team_id、squad_id、order_num。服务端会检查组织归属和目标小队；新玩家拖入已占用位置会拒绝，已经在排表中的玩家移动到已占用位置会交换两人的位置。前端必须提示真实结果，失败时保持旧界面数据，不能先显示保存成功。

“分团管理”菜单当前由后端返回的动态路由生成，父菜单 component 是 ParentView，约战排表 component 是 guild/schedule/index。推荐仅在对应动态路由父节点内补入占位子页面，不修改数据库菜单或现有权限。只在用户本来能看到该分团入口时添加占位入口，并避免重复插入。

## 5. 数据兼容，不静默删人

- 实际成员分配以服务端 teams → squads → members 为准，使用稳定 ID 及 order_num 构建位置，不用数组下标代替成员位置。
- 新建小队当前服务端固定 max_members=6，前端同样限制六个位置。
- 旧表格区域小队可能有大于六的人数上限。迁移展示六个标准位置时，超出/无效位置的旧人员必须以显式兼容提示和人员列表保留，可移动到标准位置；不自动丢弃、清空或缩编旧记录。
- 现有临时玩家 member_id 形如 temp_...；分配 API 参数是整数且要求正式成员存在，不能将临时 ID 伪造为正式成员 ID。
- 原 workbook.custom.guildScheduleTempMembers 存储临时名单。盒子临时位置若使用同一 workbook 的新增命名空间保存，应保留所有旧 sheets、styles、custom 数据，并在保存历史前等待元数据保存完成。
- 元数据按真实团队/小队/位置 ID 关联。恢复历史会生成新的团队/小队 ID，必须通过恢复后的结构重建关联，不能盲目使用历史 ID。
- 若不能可靠完成旧临时位置映射，应显式显示待重新安排，不宣称已恢复位置，不写入永久成员库。
- 当前编辑表格 UI 必须从右侧移除。旧历史的只读表格/导出能力可作为兼容入口保留，不再作为新排表主视图。

团队重命名、席位职业限制、公开报名、可复用模板及机器人不是本轮完整目标的替代品；是否随本轮附加开发需单独确认，不能借本轮界面请求扩展后端或改库。
