# 主小程序统一注册实施方案

用户已确认：复用现有后端注册逻辑，小程序和网页共用账号，不自动加入组织。

1. 补隔离回归：统一接口调用原受限流和缓存清理装饰的注册入口；注册关闭、确认密码、参数及敏感信息校验；沿用默认 user 角色。
2. 新增 POST /api/v1/auth/register，接收 userName、password、confirmPassword、可选 code／uuid，返回统一信封；不创建第二套用户表。
3. 共用 JavaScript SDK 补公开 register 方法，仅更新规范 SDK 和当前主小程序，不更新两个停用小程序。
4. 当前登录页提供“注册账号”，新增简单浅色注册页，实时读取注册／验证码开关、校验和防重复点击，失败保留输入且刷新验证码，成功清密码并返回登录，不冒充已登录。
5. npm test、后端无外部连接隔离测试；仅重启经进程校验的新版 9101 后端。不改原项目／原 ruoyi，不迁移数据库，不操纵桌面，不自动 Git 提交。
6. 联调使用独立开发库；优先只读验证实际路由与配置，不自动创建正式或演示永久账号。用户自行编译并测试实际注册。

账号 2–20 字、密码 5–20 字，与现有网页注册表单一致；密码沿用原非法字符限制；角色、账号唯一性、验证码和账号写入仍由原注册业务负责。
