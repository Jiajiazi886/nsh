# AI 连接工作台设计

## 目标

将“系统管理 / AIKey 管理”从单个 Mimo 密钥表单升级为可管理多个 OpenAI 兼容连接的工作台。全系统始终只有一个“当前使用”连接；管理员切换后，内功图片识别等现有 AI 能力在下一次请求时立即使用新连接。

## 产品结构

页面保留 RuoYi 布局，内容区采用紧凑、清晰的浅色工作台：

- 顶部显示当前生效连接、模型、协议和配置状态。
- 左侧是连接列表，可新增、编辑、删除、搜索、设为当前。
- 中间是连接编辑器，管理名称、提供商、Base URL、API Key、协议、模型 ID、输出上限、温度、图片能力和备注。
- 支持用当前表单或已保存连接读取上游模型列表，同时允许手动填写模型 ID。
- 右侧是真实连接测试区，支持多轮文字和图片消息；测试可选任意连接，不改变全系统当前连接。

## 数据与安全

- 复用 `ai_models` 表，不新增重复的密钥表。
- `status='0'` 表示全系统当前连接，`status='1'` 表示备选；服务层在同一事务中先取消旧当前项，再激活新当前项。
- API Key 继续用 `CryptoUtil` 加密入库，列表、详情、日志和错误都不返回明文。编辑时留空表示保留原密钥。
- 上游探测可使用未保存的表单密钥，也可按配置 ID 由后端解密；任何情况都不把已保存密钥发回浏览器。
- 所有管理和测试接口继续要求 `system:aikey:edit` 权限和管理员身份。

## 运行时路由

`InternalPowerMimoService` 每次识别前从数据库读取当前连接，并动态使用其 API Key、Base URL、模型 ID、协议、输出上限和温度。

- `chat_completions`：调用 OpenAI 兼容的 `chat.completions.create`。
- `responses`：调用 `responses.create`。
- 当前连接未配置密钥、未标记支持图片或缺少必填字段时，在发送图片前直接拒绝并给出可操作的错误。

测试对话复用同一运行时客户端构建逻辑，但不修改当前连接。

## 兼容性

- 现有 `__internal_power_mimo__` 记录作为首个当前连接迁移，其模型 ID 从当前 Mimo 环境配置补齐。
- 保留原 `/system/ai-key/internal-power` 接口作为短期兼容层，新页面使用 `/system/ai-key/connections` 系列接口。
- 不修改用户登录、AI 次数扣除、历史记录和业务结果校验。

## 验收

- 可保存至少两个连接，列表不泄露 API Key。
- 切换当前连接后，下一次内功图片识别使用新连接的 Base URL、Key、协议和模型。
- 上游模型获取、手动模型、多轮对话和图片测试可用。
- 测试其他连接不影响生效配置。
- 保留旧页面的密钥安全、权限和日志脱敏保障。
