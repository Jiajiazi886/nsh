# 数据库表作用总览

更新日期：2026-09-17

本文档对应 `xiaochengxu` 分支当前新版开发库 `nsh_activity_dev_20260914`。开发库审计时共有 58 张业务表。文档只描述表的用途，不包含玩家姓名、微信号、密码哈希、Token 或真实业务数据。

## GitHub 与部署数据同步规则

- GitHub 保存数据库基础结构、功能迁移 SQL、菜单初始数据、开发种子工具和审计工具。
- GitHub 不保存 `.env`、Token、真实密码、私钥、运行日志或开发库的真实行数据导出。
- 新 MySQL 部署需要按顺序导入：`ruoyi-fastapi.sql` → `20260914_activity_information_mysql.sql` → `20260914_player_profile_mysql.sql` → `20260914_activity_information_menus.sql`。
- Docker Compose 新建空数据卷时会按 `01` 到 `04` 的顺序自动导入上述文件。已经有数据的 MySQL 数据卷不会重复初始化，必须先备份再单独执行未应用的迁移。
- `tools/seed_activity_dev.py` 只用于本地演示库，密码由本机 `NSH_DEMO_PASSWORD` 环境变量提供，不应在公网生产库执行。

## 1. 系统、权限与运维

| 表名 | 作用 |
| --- | --- |
| `app_schema_migration` | 记录已执行的应用级数据迁移版本，防止同一迁移重复执行。 |
| `sys_user` | 网页、小程序共用的认证账号主表，包含登录名、密码哈希、状态和基础账号资料。 |
| `sys_role` | 系统角色定义，例如超级管理员、帮会管理和帮会成员。 |
| `sys_user_role` | 账号与角色的多对多关系。 |
| `sys_menu` | 网页菜单、路由、按钮权限标识和显示顺序。 |
| `sys_role_menu` | 角色可见菜单及可用按钮权限。 |
| `sys_dept` | 若依组织架构的部门树。帮会和俱乐部业务不直接依赖该表。 |
| `sys_role_dept` | 数据权限中角色可访问的部门范围。 |
| `sys_config` | 系统级键值配置，包括注册、默认配额等运行参数。 |
| `sys_dict_type` | 字典分类定义。 |
| `sys_dict_data` | 各字典分类下的实际选项值。 |
| `sys_notice` | 系统公告与通知内容。 |
| `sys_job` | 定时任务定义和启停状态。 |
| `sys_job_log` | 定时任务每次执行的结果与异常记录。 |
| `apscheduler_jobs` | APScheduler 持久化的调度任务运行数据。 |
| `sys_logininfor` | 登录日志，用于审计登录成功、失败和来源信息。 |
| `sys_oper_log` | 后台操作日志，记录路由、操作类型和结果。 |
| `gen_table` | 代码生成器中的业务表配置。 |
| `gen_table_column` | 代码生成器中的字段级配置。 |
| `ai_models` | 可选 AI 模型的系统配置和启用状态，不应保存明文 API Key。 |

## 2. 帮会、成员与职业

| 表名 | 作用 |
| --- | --- |
| `guild_member` | 帮会成员名册，包含玩家名、职业、帮会内身份、有效状态及可选绑定账号。 |
| `guild_profession` | 系统可用职业清单、排序和启用状态。 |
| `guild_class_color` | 按账号保存职业背景色和文字色，网页与小程序共用。 |
| `guild_join_application` | 用户申请加入帮会的记录与处理状态。 |
| `guild_team` | 旧版帮会团队定义。新版约战阵容以活动快照为主，该表仅为历史兼容。 |

## 3. 旧版约战、排表与报名兼容

| 表名 | 作用 |
| --- | --- |
| `guild_battle` | 旧版约战主记录，也承载 CSV 导入后的场次基础信息。 |
| `guild_battle_record` | 每场战斗中玩家级 CSV 统计明细，供战报和分析盒子使用。 |
| `guild_battle_invite` | 旧版约战报名或邀请链接，包含邀请码与过期时间。 |
| `guild_battle_registration` | 旧版报名、请假、审批等申请记录，保留供历史数据与兼容接口使用。 |
| `guild_schedule` | 旧版排表主表，用于保存一份帮会排表版本。 |
| `guild_schedule_team` | 旧版排表中的团定义。 |
| `guild_schedule_squad` | 旧版排表中的小队定义。 |
| `guild_schedule_assignment` | 旧版排表中成员与团、小队、位置的分配关系。 |
| `guild_schedule_workbook` | 已退役的自由表格排表 JSON 数据，仅为历史数据保留，新页面不再编辑它。 |

## 4. 新版共享约战与小程序互通

| 表名 | 作用 |
| --- | --- |
| `integration_organization` | 统一的帮会/俱乐部组织主表，保存组织类型、名称、所有者与旧数据来源关系。 |
| `integration_organization_member` | 俱乐部等新版组织的账号成员和角色关系。 |
| `integration_activity` | 新版约战活动主表，是网页与小程序的统一数据源，包含时间、组织、公开状态、修订号和最新快照。 |
| `integration_activity_snapshot` | 每次管理员点击保存时产生的不可变阵容快照，保存团、小队、六个位置、玩家、职业要求和备注。 |
| `integration_activity_participation` | 账号参加活动的实时状态，包括管理员安排、公开报名、离开及当前座位。 |
| `integration_activity_receipt` | 活动写操作的幂等回执，防止网络重试造成重复保存、重复报名或重复发布。 |
| `integration_activity_report` | 新版活动与 `guild_battle` CSV 战报场次的明确关联，不使用名称或日期猜测匹配。 |
| `integration_activity_leave_link` | 帮会活动自动生成的公开请假链接编码。 |
| `integration_activity_leave_record` | 活动请假人、当时玩家快照、备注与请假时间；请假后阵容读取会自动移除该成员。 |
| `integration_account_player_profile` | 每个认证账号唯一的玩家资料，包含名字、字符串 UID、微信号、橙武开关、主副职业和备注。微信号属于受限个人数据。 |
