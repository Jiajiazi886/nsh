## 1. 文档目的

本文件详细说明“约战信息”功能在网页端、微信小程序和共享后端之间如何协作。

重点回答以下问题：

1. 普通用户、管理员和助手分别能做什么。
2. 网页和小程序共同拥有的功能有哪些。
3. 哪些功能共用同一份后端数据，但交互方式不同。
4. 哪些管理能力当前只在网页端提供。
5. 创建约战、配置阵容、保存快照、公开报名、请假和战报查看如何连接起来。
6. 账号、玩家资料、帮会成员、组织、活动和战报为什么不能混为一张表。
7. 网络错误、权限不足、并发保存和重复提交时系统如何处理。

本文描述的是当前代码和当前开发库中真实存在的能力，不使用假活动或假接口补充页面。

## 2. 功能总体定位

“约战信息”不是一个单独的活动列表，而是一套完整的活动协作流程：

```text
统一账号登录
    ↓
管理员／助手创建约战
    ↓
网页端配置团队、小队、六个位置和职业要求
    ↓
点击保存，生成组织成员可见的阵容快照
    ↓
所属成员在网页和小程序查看同一活动、同一阵容版本
    ↓
管理员明确发布公开
    ↓
符合职业要求的用户在网页或小程序报名／请假
    ↓
管理员结束活动，阵容冻结并进入历史
    ↓
明确关联 CSV 战报
    ↓
网页和小程序读取同一份历史活动及战报数据
```

该功能的核心原则是：

- 网页和小程序不是两套业务系统。
- 两端使用同一个后端、同一个账号体系、同一个活动 ID 和同一份数据库数据。
- 小程序不会在接口失败时切换成假活动。
- 本地草稿不等于成员可见阵容。
- 保存阵容不等于公开发布。
- 公开报名不等于获得阵容编辑权限。
- 临时替补不等于永久帮会成员。
- 活动战报必须明确关联，不能按标题或日期猜测。

## 3. 三端系统结构

```text
┌─────────────────────────────┐
│ 网页前端 Vue 3 · 5173       │
│ 创建约战、拖拽排表、管理活动 │
└──────────────┬──────────────┘
               │ /dev-api → /api/v1
               │
┌──────────────▼──────────────┐
│ FastAPI 后端 · 9101         │
│ 认证、权限、校验、事务、接口 │
└──────────────┬──────────────┘
               │
      ┌────────┴────────┐
      │                 │
┌─────▼──────────┐ ┌────▼────────────┐
│ MySQL           │ │ Redis DB15      │
│ 业务持久化数据   │ │ 字典与运行缓存  │
└─────▲──────────┘ └────▲────────────┘
      │                 │
┌─────┴─────────────────┴─────┐
│ 微信小程序                    │
│ 查看活动、查看阵容、报名、请假 │
└─────────────────────────────┘
```

### 3.1 网页前端

网页端主要承担管理和大屏幕编辑任务：

- 创建约战。
- 创建俱乐部。
- 选择明确的活动进入约战排表。
- 拖拽玩家进入位置。
- 创建、删除、改名和折叠团队／小队。
- 设置位置指定职业。
- 创建当前活动临时替补。
- 每 10 秒保存本地草稿。
- 点击“保存”生成后端阵容快照。
- 发布公开、结束活动、关联战报。
- 查看“我的约战”“找约战”“历史战报”和详情。

### 3.2 微信小程序

小程序主要承担随时查看和本人操作：

- 使用与网页相同的账号密码登录。
- 注册同一套后端账号。
- 查看帮会活动、俱乐部活动、公开活动和历史战报。
- 查看管理员已经保存的团队、小队和六席阵容。
- 查看空缺位置与指定职业。
- 使用本人有效绑定角色报名空位。
- 对本人已占位置执行请假／离位。
- 读取活动已经明确关联的战报。
- 编辑与网页共用的个人玩家资料。
- 读取与网页一致的职业颜色。

当前小程序不提供鼠标式阵容管理。管理员在小程序点击“管理阵容说明”时，会明确提示到网页端完成排表和保存。

### 3.3 共享后端

后端负责真正决定操作是否允许：

- 校验登录 Token 和账号状态。
- 判断用户是否属于组织。
- 判断用户是普通成员、助手还是管理员。
- 校验报名角色是否属于当前账号。
- 校验位置职业要求。
- 防止同一位置被多人占用。
- 防止同一成员重复报名。
- 校验活动版本，阻止无提示覆盖他人修改。
- 使用事务保存阵容和快照。
- 使用操作标识防止重复请求。
- 控制私人微信号等信息的可见范围。
- 对网页和小程序返回相同的数据契约。

- 创建、删除、改名和折叠团队。
- 创建、删除和改名小队。
- 拖拽玩家进入位置。
- 队内移动、跨队移动和双方交换。

- 本人本地分析状态。

这些导入数据属于当前账号的本机数据，不是共享活动数据，也不会在网络失败时冒充后端战报。

## 5. 统一账号、注册和登录

### 5.1 同一账号

网页和小程序直接使用后端的 `sys_user` 账号：

- 网页账号可以登录小程序。
- 小程序注册的账号可以登录网页。
- 不为小程序单独创建另一张用户表。
- 不根据玩家昵称自动创建账号。
- 不把微信号当作登录账号。
- 当前没有接入微信一键登录或微信授权绑定。

### 5.2 登录流程

```text
打开网页／小程序
    ↓
读取登录配置和验证码配置
    ↓
提交账号、密码、验证码
    ↓
后端校验账号状态并签发 JWT
    ↓
客户端请求当前账号信息
    ↓
确认会话有效后进入系统
```

### 5.3 密码与 Token

- 密码只用于登录／注册请求，不写入小程序本地缓存。
- 业务请求使用 `Authorization: Bearer <token>`。
- Token 存在不等于账号一定有效，重新进入时需要向服务器确认。
- 返回 401 时清理失效会话并回到登录页。
- 网络断开和认证失效要区分：断网时提示重试，不能直接声称账号失效。
- 切换后端地址时，旧地址的会话不能继续用于新地址。

### 5.4 注册

注册是否可用由后端配置决定。两端读取同一个注册开关和验证码开关。

注册成功只创建登录账号，不自动完成以下操作：

- 不自动加入帮会。
- 不自动创建帮会成员。
- 不自动绑定微信身份。
- 不自动创建游戏玩家资料。
- 不自动获得管理员／助手权限。

## 6. 个人玩家资料

网页和小程序使用同一个个人资料接口，一个认证账号维护一份资料。

### 6.1 字段

| 字段 | 说明 |
| --- | --- |
| 名字 | 游戏玩家名，必填，最多 30 字 |
| 玩家 UID | 游戏 UID，按字符串保存，可保留前导零 |
| 微信号 | 手动填写的联系方式，不等于微信账号绑定 |
| 橙武 | 布尔开关，默认关闭 |
| 主职业 | 报名和职业展示使用的主要职业 |
| 副职 | 辅助职业信息 |
| 备注 | 最多 500 字 |

### 6.2 未加入帮会也可以填写

个人资料属于登录账号，而不是某一条帮会成员记录。因此：

- 未加入帮会的账号也可以填写个人资料。
- 保存个人资料不会自动加入帮会。
- 有效绑定帮会成员存在时，公开成员字段会在同一事务中同步。
- 保存失败时不能只更新一半数据。

### 6.3 微信号权限

微信号属于私人信息：

- 本人可以查看。
- 本帮会管理员或助手在真实组织权限校验通过后可以查看。
- 普通成员不可查看其他人的微信号。
- 组织外用户不可查看。
- 俱乐部管理身份不能自动跨越帮会隐私权限。
- 公开活动接口不返回微信号。
- 后端日志对微信号执行脱敏。

## 7. 组织与角色

### 7.1 组织类型

统一活动系统支持两种组织：

| 类型 | 用途 |
| --- | --- |
| 帮会 `guild` | 复用现有帮会成员、职业和管理关系 |
| 俱乐部 `club` | 独立的轻量活动组织，由所有者授权成员和助手 |

### 7.2 组织身份

| 身份 | 主要权限 |
| --- | --- |
| 所有者／管理员 `owner` | 创建和管理本组织活动、保存阵容、发布、结束、关联战报 |
| 助手 `assistant` | 在所属组织范围内协助排表和管理活动 |
| 普通成员 `member` | 查看本组织已保存活动与阵容，参加公开报名 |
| 组织外用户 | 只能查看公开活动；符合条件时可报名 |

权限依据是后端真实账号和组织成员关系，不依赖：

- 玩家昵称。
- 页面是否隐藏按钮。
- 前端传来的“我是管理员”标记。
- 平台角色对所有组织的默认越权。

## 8. 约战信息四类界面

### 8.1 我的约战

“我的约战”展示当前账号所属组织的未结束活动。

网页端：

- 帮会活动显示在左侧。
- 俱乐部活动显示在右侧。
- 管理员和助手可以看到创建约战入口。
- 每张活动卡展示名称、组织、活动状态、约战时间、已排人数、总席位、职业缺口和战报状态。

小程序：

- 使用“帮会活动”和“俱乐部活动”两个顶部分类。
- 每个分类单独向后端提交 `orgType`，避免一个分类被另一类活动挤出第一页。
- 支持分页加载更多。
- 点击活动进入同一个活动详情。

### 8.2 找约战

“找约战”只展示管理员已经明确发布公开且仍处于开放状态的活动。

用户可以查看：

- 活动名称。
- 发起组织。
- 约战时间。
- 空缺席位数量。
- 每个职业缺少人数。
- 是否已经关联战报。

网页端还支持：

- 按职业需求筛选。
- 仅查看存在空位的活动。

组织外用户可以访问公开活动，但不能因此读取组织内部活动或获得排表编辑权限。

### 8.3 历史战报

历史范围包括：

- 当前账号所属组织的已结束活动。
- 当前账号本人参加过的公开活动。
- 有权限查看的已关联战报。

没有关联 CSV 时显示“暂无战报数据”，不会生成虚构统计。

旧战报没有明确活动关联时继续保留，并标记为未关联，不根据活动名称或日期自动猜配。

### 8.4 约战详情

详情页是前三类列表的共用页面，不作为独立菜单项。

详情内容包括：

- 活动名称。
- 所属帮会或俱乐部。
- 组织内部／公开报名／已结束状态。
- 约战时间。
- 活动说明。
- 当前活动修订号。
- 当前阵容快照版本和保存时间。
- 团队、小队和六个位置。
- 位置指定职业。
- 玩家姓名、职业和临时替补标记。
- 空缺位置。
- 报名、请假和战报入口。

普通成员读取的是管理员最后一次成功保存的快照，不读取管理员尚未提交的本地草稿。

## 9. 创建约战

### 9.1 当前创建入口

当前创建约战在网页“我的约战”页面中提供。只有至少管理一个组织的管理员或助手能看到入口。

创建时填写：

| 字段 | 规则 |
| --- | --- |
| 所属组织 | 必须选择一个本人有管理权限的帮会或俱乐部 |
| 活动名称 | 必填，最多 100 字 |
| 约战时间 | 单一时间字段，默认最近周二／周四 20:30，可手动修改 |
| 说明 | 最多 500 字，对外可见，不应填写密码或私人联系方式 |

### 9.2 约战时间规则

业务界面不存在“开始时间”和“结束时间”，只有“约战时间”。

默认时间为最近一个尚未错过的周二或周四 20:30：

```text
周一或周二 20:30 前 → 本周二 20:30
周二 20:30 后         → 本周四 20:30
周三                   → 本周四 20:30
周四 20:30 前         → 本周四 20:30
周四 20:30 后         → 下周二 20:30
周五、周六、周日       → 下周二 20:30
```

日期选择器显示到分钟，不要求用户设置秒。

为了兼容现有数据库和旧接口，程序内部仍会把“约战时间”映射到历史时间字段；这是存储兼容细节，不再作为两个可配置的业务时间展示给用户。

### 9.3 创建后的状态

创建成功后：

- 活动默认是组织内部活动。
- 活动状态为开放。
- 尚无阵容快照。
- 普通成员会看到“管理员尚未保存阵容”。
- 管理员会进入与该活动 ID 明确关联的约战排表。
- 创建活动不会自动公开。

## 10. 网页约战排表

### 10.1 必须明确关联活动

排表不能脱离活动存在。进入排表时必须：

- 从活动详情点击“配置排表”；或
- 在约战排表入口选择一个本人可管理的明确活动。

所有本地草稿、保存请求和快照都以稳定的 `activityId` 作为归属，不能按活动名称猜测。

### 10.2 团队和小队

排表层级为：

```text
活动
└─ 团队／团
   └─ 小队
      ├─ 位置 1
      ├─ 位置 2
      ├─ 位置 3
      ├─ 位置 4
      ├─ 位置 5
      └─ 位置 6
```

规则：

- 活动可以包含多个团队。
- 团队可以创建、删除、改名和折叠。
- 团队本身不直接放玩家。
- 团队内可以创建多个小队。
- 小队可以创建、删除和改名。
- 每个小队固定六个位置。
- 删除团队或小队后，位置中的玩家回到候选区。
- 删除只修改本地草稿，点击保存后才影响其他成员看到的阵容。

### 10.3 候选玩家

候选玩家来自当前组织允许安排的成员：

- 帮会排表只能安排本帮会成员。
- 俱乐部排表只能安排已经明确授权的成员。
- 候选区按职业树分类。
- 每个职业使用统一颜色。
- 职业树默认全部收起。
- 可以按玩家名或职业搜索。
- 已安排玩家仍可在候选区看到“已排”状态。

### 10.4 玩家安排

网页取消了位置内的“选择玩家”按钮和点击选人弹窗。

玩家安排只通过拖拽完成：

- 从候选区拖入空位。
- 从一个位置移动到另一个空位。
- 队内交换两个玩家。
- 跨队交换两个玩家。
- 点击小型“移出”按钮把玩家放回候选区。

安排玩家不会刷新整张页面，只更新当前 Vue 状态和本地草稿。

### 10.5 指定职业

每个位置可以设置：

- 不限职业。
- 指定某一个启用职业。

职业要求使用统一颜色标签显示。

拖拽和交换都需要校验双方：

- 玩家职业不符合目标位置时拒绝操作。
- 交换时如果任意一端不符合新位置要求，整次交换失败。
- 校验失败显示具体原因。
- 校验失败不会修改原阵容。

### 10.6 临时替补

管理员或助手可以为当前活动创建临时替补：

- 必须填写临时玩家名称和职业。
- 临时替补可以像正常成员一样被拖入位置。
- 临时替补带有明确的临时标记。
- 只保存在当前活动阵容／快照中。
- 不写入永久帮会成员名册。
- 不获得组织访问权限。
- 不允许借临时身份读取组织私有数据。

## 11. 本地草稿与后端快照

### 11.1 每 10 秒本地保存

管理员编辑排表时，每 10 秒把草稿写入浏览器 IndexedDB。

本地草稿的特点：

- 只属于当前浏览器和当前账号。
- 按后端地址、账号 ID 和活动 ID 隔离。
- 不会更新其他用户界面。
- 不会让小程序看到未提交修改。
- 刷新或离开页面后可以恢复。
- 保存失败时保留，防止网络问题导致排表丢失。

### 11.2 点击“保存”

只有点击“保存”才向后端提交完整阵容。

后端成功后：

- 生成新的阵容快照。
- 更新活动的最新快照 ID。
- 增加活动修订号。
- 普通成员和小程序读取新快照。
- 旧快照继续保留。

后端失败后：

- 不替换上一份成功快照。
- 普通成员继续看到旧版本。
- 本地草稿继续保留。
- 页面显示错误和重试信息。

### 11.3 历史快照

管理员可以查看本活动的历史快照，并加载到本地草稿。

加载历史快照：

- 只替换当前本地草稿。
- 不会立即修改后端。
- 需要再次点击“保存”才会生成新的成员可见版本。
- 不会覆盖或删除原历史快照。

## 12. 发布公开与报名

### 12.1 保存不等于发布

活动有三种容易混淆的状态：

| 动作 | 结果 |
| --- | --- |
| 创建活动 | 建立组织内部活动，尚无阵容 |
| 保存阵容 | 组织成员可以查看最新快照，但仍不一定公开 |
| 发布公开 | 活动进入“找约战”，组织外用户可以查看和报名 |

管理员必须先保存有效阵容，才能公开发布。

### 12.2 谁可以报名

报名者必须：

- 已登录。
- 活动已经公开。
- 活动仍处于开放状态。
- 活动存在已保存阵容。
- 使用属于本人账号的有效绑定角色。
- 目标位置为空。
- 角色职业符合位置要求，或位置为不限职业。

报名者不要求属于活动发起帮会，因此组织外用户也可以参加公开抢凳子活动。

### 12.3 报名校验

后端会拒绝：

- 冒用别人的成员 ID。
- 职业不符合指定位置。
- 位置已经被其他人占用。
- 同一成员在同一活动重复报名。
- 同一成员同时占多个位置。
- 活动未公开。
- 活动已结束或当前不可报名。
- 没有已保存阵容。

### 12.4 请假／离位

用户可以对本人已经占用的位置执行请假：

- 只能操作本人绑定角色。
- 请假成功后位置重新显示为空缺。
- 其他用户随后可以报名。
- 普通用户不能把其他玩家移出。
- 公开报名位置不能被管理员无提示覆盖。

## 13. 小程序活动详情交互

小程序活动详情是只读阵容与本人报名入口。

### 13.1 查看阵容

小程序展示：

- 团队名称。
- 小队名称。
- 小队已有人数／六席。
- 六个位置编号。
- 空缺位置的高亮状态。
- 位置指定职业。
- 已占位置的玩家名和职业。
- 临时替补标记。

### 13.2 点击空位报名

用户点击空位时：

1. 小程序确认活动当前允许报名。
2. 向后端读取本人有效绑定角色。
3. 按主职业生成默认收起的职业树。
4. 用户展开职业并选择本人角色。
5. 小程序先进行职业提示校验。
6. 提交报名请求。
7. 后端再次进行最终权限、职业和位置校验。
8. 成功后重新读取活动详情和最新修订号。

前端校验只是为了及时提示，后端校验才是最终安全边界。

### 13.3 点击已占位置

如果位置已经有人，小程序只显示“已占用：玩家名”，不会打开报名界面，也不会允许覆盖。

### 13.4 请假

“本人请假／离位”会：

1. 读取本人有效绑定角色。
2. 找到阵容中属于本人的位置。
3. 如果存在多个本人角色，显示操作列表。
4. 用户选择要请假的角色。
5. 提交请假请求并刷新活动详情。

## 14. 结束活动与历史冻结

管理员在网页端明确执行“结束活动并冻结阵容”。

结束后：

- 活动状态变为已结束。
- 不再接受新的公开报名。
- 阵容作为最终活动阵容保留。
- 活动进入历史战报列表。
- 历史阵容和旧快照不会被个人资料更新追改。
- 本人参加过的公开活动可以进入本人历史范围。

结束活动需要二次确认，避免误操作。

- 网页显示“暂无战报数据”。
- 小程序显示“暂无战报数据”。
- 不生成假玩家或假统计。
- 不使用小程序本地 CSV 冒充共享战报。

## 18. 并发、事务和防重复提交

### 18.1 活动修订号

每个活动有 `revision`：

- 保存阵容会增加修订号。
- 发布、结束、报名和请假也会增加修订号。
- 客户端写入时提交 `expectedRevision`。
- 后端发现版本不一致时返回冲突，要求重新读取确认。
- 不允许后打开的旧页面无提示覆盖别人刚保存的内容。

### 18.2 操作标识

每次写操作携带唯一 `operationKey`：

- 网络超时后可以使用同一个标识安全重试。
- 同一个活动、操作者和操作标识只对应一次业务操作。
- 同一标识不能被拿来提交另一份不同内容。
- 已经成功的请求重复到达时，后端返回原结果，避免重复快照或重复报名。

### 18.3 数据库事务

保存阵容时需要在同一事务中完成：

- 校验活动和权限。
- 校验修订号。
- 校验团队、小队、六席和玩家身份。
- 校验职业要求。
- 写入新快照。
- 更新活动最新快照和修订号。
- 写入操作凭据。

任意一步失败都回滚，不能出现“快照写了一半”或“活动指向不存在快照”的状态。

## 21. 错误处理

### 21.1 不回退假数据

以下情况必须显示真实错误：

- 后端未启动。
- 数据库连接失败。
- Token 失效。
- 用户没有权限。
- 活动不存在或不可见。
- 活动版本冲突。
- 职业不符合。
- 位置已占。
- 保存事务失败。
- 战报不存在或无权限。

网页和小程序不能在这些情况下显示内置演示活动来冒充连接成功。

### 21.2 重试

- 活动列表提供重试入口。
- 活动详情可以重新读取。
- 保存失败保留本地草稿。
- 网络结果不确定时复用原 `operationKey`。
- 版本冲突要求用户重新读取后端并确认。
- 小程序账号失效后返回登录页。

```text
→ 我的约战
→ 创建约战
→ 选择组织、填写名称
→ 确认默认约战时间或手动修改
→ 创建并进入排表
→ 创建团队和小队
→ 设置位置职业
→ 从职业树拖入帮会成员
→ 必要时创建当前活动临时替补
→ 等待每 10 秒本地保存，或直接点击保存
→ 后端生成阵容快照
→ 检查详情
→ 发布公开
```

### 23.2 普通成员查看

```text
成员登录网页或小程序
→ 我的约战
→ 选择帮会／俱乐部活动
→ 查看活动详情
→ 查看管理员最后一次成功保存的阵容版本
```

### 23.3 外部用户抢凳子

```text
外部用户登录网页或小程序
→ 找约战
→ 查看公开活动职业缺口
→ 进入详情
→ 点击空缺位置
→ 选择本人有效绑定角色
→ 后端校验职业和位置
→ 报名成功
→ 两端重新读取后显示该位置已占用
```

### 23.4 请假

```text
用户进入活动详情
→ 选择本人请假／离位
→ 确认本人角色
→ 后端校验身份和活动版本
→ 清除本人占位
→ 空位和职业缺口恢复
```

### 23.5 结束与战报

```text
管理员确认比赛结束
→ 网页结束活动
→ 阵容冻结并进入历史
→ 导入或找到已有 CSV 战报
→ 输入战报 ID 明确关联活动
→ 网页和小程序历史页显示已有战报
```

## 24. 验收检查清单

### 24.1 账号互通

- [ ] 同一个账号可以登录网页和小程序。
- [ ] 两端读取到相同账号 ID。
- [ ] 小程序注册账号可以登录网页。
- [ ] 密码没有写入本地存储。
- [ ] 退出后业务接口不能继续使用旧 Token。

### 24.2 活动列表

- [ ] 网页和小程序能看到同一个活动 ID。
- [ ] 帮会活动和俱乐部活动分类正确。
- [ ] 私有活动不能被组织外账号读取。
- [ ] 发布后同一活动出现在“我的约战”和“找约战”。
- [ ] 历史范围包含本组织历史和本人参加的公开历史。

### 24.3 创建时间

- [ ] 创建弹窗只有一个“约战时间”。
- [ ] 周二场次前默认本周二 20:30。
- [ ] 周二场次后默认本周四 20:30。
- [ ] 周四场次后默认下周二 20:30。
- [ ] 用户可以手动修改。
- [ ] 列表和详情不再显示“开始时间至结束时间”。

### 24.4 排表与快照

- [ ] 团队可创建、删除、改名和折叠。
- [ ] 小队可创建、删除和改名。
- [ ] 每个小队固定六席。
- [ ] 玩家只通过拖拽安排。
- [ ] 职业不符时原阵容不变。
- [ ] 交换时双方职业要求都被校验。
- [ ] 每 10 秒本地保存不会更新小程序。
- [ ] 点击保存后小程序读取相同快照版本。
- [ ] 后端保存失败时普通成员仍看到上一版本。

### 24.5 临时替补

- [ ] 临时替补可以进入当前阵容。
- [ ] 快照中保留临时标记。
- [ ] 不写入永久 `guild_member`。
- [ ] 不获得组织访问权限。
- [ ] 不影响其他活动。

### 24.6 报名和请假

- [ ] 组织外账号可以查看公开活动。
- [ ] 符合职业要求时可以报名。
- [ ] 职业不符合时明确拒绝。
- [ ] 已占位置不能重复报名。
- [ ] 用户不能冒用其他成员 ID。
- [ ] 请假后空位和职业缺口恢复。
- [ ] 报名权限不会授予排表编辑权限。

### 24.7 战报

- [ ] 没有 CSV 时显示“暂无战报数据”。
- [ ] 战报必须通过 ID 明确关联。
- [ ] 未关联旧战报继续保留。
- [ ] 网页和小程序读取同一关联结果。
- [ ] 公开接口不返回原始文件路径或私人信息。

## 25. 当前边界与后续方向

当前尚未包含：

- 微信一键登录。
- 微信账号绑定。
- iLink 微信机器人实际接入。
- 小程序完整管理员排表编辑。
- 小程序创建约战。
- 跨设备同步管理员未提交的本地草稿。
- 自动根据活动名称或日期匹配战报。
- 把小程序本地 CSV 自动上传为共享战报。

后续机器人接入时应复用现有后端能力：

- 查询当前公开活动数量。
- 查询某职业仍有缺口的公开活动。
- 查询本人已报名活动。
- 通知符合职业要求的用户。

机器人不能绕过现有权限、报名资格、职业校验或私人信息保护规则。

---

## 26. 一句话总结

约战信息是一套由网页负责管理排表、由网页和小程序共同查看与报名、由共享后端统一执行账号认证、权限校验、阵容快照、并发保护和战报关联的多端活动系统；两端看到的是同一个活动、同一份成功保存的阵容和同一份历史结果，而不是各自维护的演示数据。
